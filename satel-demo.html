🧪 SATEL for Algebraic Petri Nets

Semi-Automatic Testing Language

Based on Levi Lucio's PhD Thesis (Geneva, 2009)

Overview

This project implements SATEL (Semi-Automatic Testing Language) concepts for Algebraic Petri Nets (APNs), adapting test intention ideas from Levi Lucio's PhD thesis on CO-OPN object-oriented specifications.

✅ Implementation Status: Core SATEL components implemented with 34 passing tests. Examples include drink vending machine and banking server.

What is SATEL?

SATEL allows you to specify test intentions — high-level descriptions of behavior you want to test — and automatically generate concrete test cases with oracles.

🎯 Test Intentions

Specify what to test (path patterns, inputs, expected outputs)

🔬 Test Generation

Automatic generation via reachability graph exploration

✅ Oracles

HML-style event sequences with positive/negative results

📉 Reduction

Uniformity, regularity, axiom-based test set minimization

Example: Drink Vending Machine

System Description

A drink vending machine that:

  • Accepts coins from users (stimulation/input)
  • Allows drink selection: water ($2) or beer ($3) (stimulation/input)
  • Dispenses drinks if payment is sufficient (observation/output)
  • Returns change if overpayment (observation/output)
  • Shows error messages (insufficient funds, out of stock)

Test Intention Example

{ "id": "buy-water-exact", "name": "Buy water with exact payment", "pathPattern": { "type": "sequence", "events": [ { "transition": "insertCoin", "binding": { "c": 2 } }, { "transition": "selectDrink", "binding": { "d": "water" } }, { "transition": "dispenseWater" } ] }, "outputExpectations": [ { "place": "dispensed", "pattern": "\"water\"" }, { "place": "change", "pattern": "0" } ], "reductionHypothesis": { "type": "uniformity", "domain": "drinks", "representative": "water" }, "oracleType": "positive" }

HML Formula (Generated)

<insertCoin(2)><selectDrink(water)><dispenseWater> => true

This intention generates test cases that verify: user inserts 2 coins, selects water, and receives water with no change. The uniformity hypothesis allows testing only "water" to represent all drinks (beer, soda, etc.) since they behave identically.

Reduction Hypotheses

Uniformity

"All drinks behave identically" → test only one representative

Example: Test "water" to cover all drinks (water, beer, soda)

Regularity

"Loop behavior is regular" → test boundary cases

Example: For loops, test 0, 1, 2, many iterations

Axiom-Based

"Transitions with same structure are equivalent" → test one per equivalence class

Example: dispenseWater and dispenseBeer have same structure (only differ in constants)

Implementation

Components

  • I/O Interface: Mark places/transitions as stimulations or observations
  • State Space Explorer: Build reachability graphs
  • Test Generator: Generate test cases from intentions
  • Oracle Generator: Create HML-style oracles
  • Reduction Engine: Apply reduction hypotheses
  • Test Executor: Run and validate tests

Examples Included

  • Drink Vending Machine (from thesis Chapter 1)
  • Banking Server (login, deposit, withdraw, logout)
